# @marktiderman/genesis-ui

Genesis's web components: elements, patterns, layouts and data-bound views on shadcn/ui and
Radix, styled only through the design system's tokens. Layer **foundation**, group **core**;
essential (every Genesis web app starts with it). The React Native counterpart is
[`genesis-ui-native`](../ui-native/README.md), with the same component names.

## Install

```bash
pnpm add @marktiderman/genesis-ui @marktiderman/genesis-design-system @marktiderman/genesis-core
```

React 19 and Tailwind CSS 4. The other peer dependencies (Radix, date-fns, recharts, Tiptap and
so on) are needed only by the components that use them.

## Entry points

| Import | What it holds |
| --- | --- |
| `@marktiderman/genesis-ui` | Every element and pattern from one place |
| `@marktiderman/genesis-ui/<component>` | One component, e.g. `/button`, `/settings-row` (smaller bundles) |
| `@marktiderman/genesis-ui/patterns` | Composed components with slots |
| `@marktiderman/genesis-ui/layout` | `AppShell`, `PageHeader`, page and detail layouts |
| `@marktiderman/genesis-ui/data` | `ResourceView`, `RecordView`, `DataPageShell`, `ResourcePage` |
| `@marktiderman/genesis-ui/hooks/*` | The hooks behind the patterns |
| `@marktiderman/genesis-ui/router/react-router`, `/router/tanstack-router` | Link and navigation adapters |
| `@marktiderman/genesis-ui/styles.css` | The component styles |

## Quick start

A list screen is a view, not a hand-built table:

```tsx
import { defineView } from "@marktiderman/genesis-core/resource-view";
import { ResourceView } from "@marktiderman/genesis-ui/data";
import { contracts } from "./resources.genesis"; // written by `genesis introspect`

const tasksView = defineView(contracts["public.tasks"], {
  columns: { default: ["title", "due", "status"], compact: ["title"] },
});

export function TasksScreen() {
  return <ResourceView view={tasksView} />;
}
```

A form with no list around it (beside a sortable list that reorders in one write, say) takes the
same view, and gets the form `ResourceView` would open: its fields, links as pickers, the viewer's
scope and the view's words.

```tsx
<ResourceForm view={tasksView} action="create" open={open} onOpenChange={setOpen} filter={{ project_id }} />
```

`useViewFormFields(view, { filter, defaults })` returns those fields for a form of your own.

The same view shows as a calendar with `mode="calendar"` (its `calendar` block, the screen's
overrides in `calendar={…}`): a layout switch (`layouts`), a weeks switch (`weeksOptions`), the
screen's own controls beside them (`toolbar`), and a colour per lane with `colorLanes`. All-day rows
are best stored as days; stored as UTC midnight they stay on their day on any clock.
`laneColor(i)` from `/data` gives the colour for lane `i`: the theme's chart colours, then distinct
ones past five. See [Calendar](../../docs/RESOURCE-VIEW.md#calendar).

```tsx
<ResourceView view={tasksView} mode="calendar" calendar={{ layouts: ["weeks", "lanes"], weeksOptions: [1, 2, 4], colorLanes: true }} />
```

Theme it with [`genesis-design-system`](../design-system/README.md): import
`@marktiderman/genesis-design-system/themes/genesis.css` and `themes/genesis-tailwind4.css` after
Tailwind, as its README shows; a brand of your own replaces them with CSS generated by
`tailwindFromBrand`.

## Sign-in pages

`AuthForm` (from the root or `/patterns`) is the web sign-in form, inside `AuthPage`: sign in with
a password, a magic link or an emailed code, sign up, forgot password and the new password a reset
link opens, with provider buttons. It draws the steps and the words; every call goes through the
`client` it is given. On Supabase that is `createAuthFormClient` from
[`genesis-supabase`](../supabase/README.md#on-the-web-authform), which also finds the providers the
project has turned on.

```tsx
import { AuthForm, useUiMessages, type AuthFormClient, type AuthFormMode } from "@marktiderman/genesis-ui";
import { AuthPage } from "@marktiderman/genesis-ui/layout";

function SignInPage({ client }: { client: AuthFormClient }) {
  const [mode, setMode] = useState<AuthFormMode>("sign-in");
  const { titles } = useUiMessages().auth;
  return (
    <AuthPage branding={{ logo: <Logo />, headline: titles[mode] }}>
      <AuthForm client={client} mode={mode} onModeChange={setMode} methods={["password", "email-code"]} onSuccess={() => navigate("/")} />
    </AuthPage>
  );
}
```

- **Modes**: `"sign-in"`, `"sign-up"`, `"forgot-password"`, `"new-password"`; controlled
  (`mode`, `onModeChange`: a route per mode) or not (`defaultMode`).
- **`methods`**: how to sign in, the first shown and the rest offered as links
  (`"password"`, `"magic-link"`, `"email-code"`, `"phone-code"`).
- **`"phone-code"`** (opt-in, through `methods`): a phone number field (`type="tel"`,
  `autocomplete="tel"`) instead of the email, a code texted to it (`client.sendPhoneCode`), and
  the same code step (`client.verifyPhoneCode`). The number must carry its country code; spaces,
  dashes and brackets are dropped (`+1 (555) 123-4567` → `+15551234567`). A client without both
  calls leaves the method out (in development it says so). Without sign-up, an unknown number is
  answered as sent, as for email.
- **`signUpFields`** (opt-in): more fields on the sign-up form, whose values go to
  `client.signUp` as `data` (on Supabase, the user's metadata, which a signup trigger reads).
  `["full_name"]` adds a required "Full name" (`autocomplete="name"`); your own are
  `{ name, label, type?, autoComplete?, placeholder?, required? }`. A function is a slot:
  `({ values, setValue, disabled }) => …` draws its own inputs. Empty optional values are left out.
- **The email beside a new password**: in `mode="new-password"`, when the email is known
  (`initialEmail`, else `client.currentEmail()`, which genesis-supabase reads from the session),
  the form holds it in a hidden `autocomplete="username"` field, so a password manager saves the
  new password with its account. Nothing changes on screen; `showAccountEmail` (opt-in) shows it
  read-only instead.
- **The code step** is `InputOTP` (`autocomplete="one-time-code"`): it verifies on the last digit,
  and resends after `resendCooldown` seconds (60).
- **`codeLength` must match the project's `otp_length`** (Supabase Auth settings, "Email OTP
  length"; default 6). The code field takes exactly `codeLength` digits, so with a mismatch no
  code can be entered whole and code sign-in fails with nothing on screen to say why. Supabase's
  public `/auth/v1/settings` doesn't report `otp_length`, so the form can't check it; in
  development a refused code logs a hint to compare the two.
- **`offerCodeOnConfirm`** (opt-in): the "check your email" screens after a magic link and after
  sign-up offer "Enter the code instead", which opens the code step for the same email. For people
  in an embedded browser (an in-app web view), where the link opens in another browser. It needs
  `"email-code"` in `methods`, and `{{ .Token }}` in the Magic Link and Confirm signup templates.
- **`notice`**: a notice above the form's first step, as an `Alert`: `{ kind: "reset-link-expired" }`,
  `"provider-cancelled"` or `"account-deleted"` with the catalogue's copy (`auth.notices`), a
  `message` of your own, or a plain string. An expired link is an error (`role="alert"`), the
  others are announced politely (`role="status"`); `tone` overrides it.
- **Before hydration** a server-rendered form's submit is disabled (drawn as enabled) and the form
  is `method="post"`, so an early click or Enter neither drops what was typed nor puts the email
  in the URL.
- **Providers**: `providers={["google"]}` or objects with a label and icon; left out, it asks
  `client.providers()`; `false` for none.
- **Words** are the `auth` part of the catalogue (`UiMessagesProvider`). A failed call shows the
  copy for its error code (`auth.errors.invalid_credentials`…), else `auth.errors.generic`. The
  server's own text is never shown: for a code with no copy it goes to `reportError`. A client
  that writes a message for people marks it `displayable: true`, and that one is shown.
- **Without sign-up** (`allowSignUp={false}`), an email with no account is answered as sent
  (Supabase's `otp_disabled`), in neutral copy ("If … has an account, we sent…"), so the form
  never tells which emails have accounts.
- **`mode="new-password"`** needs the session a reset link opens: show it only after the client's
  `PASSWORD_RECOVERY` event.
- Every field is labelled and carries the autocomplete a password manager needs (`email`,
  `current-password`, `new-password`); errors are announced and tied to the field their code is
  about (`weak_password` to the password, `email_*` and `user_already_exists` to the email).
  "Check your email" takes focus when it replaces the form, and the code field stays focusable
  (read-only, `aria-busy`) while it verifies.
- Native's `AuthForm` (genesis-ui-native) is a different component: it takes `onSubmit` and
  `errorMessage`, and its `mode` is `password` or `magic-link`.

## Messaging: `ThreadPage`, `InboxPage` and `InboxLayout`

The web twins of genesis-ui-native's messaging layouts, with the same props and slots, on the
shared conversation contract in `@marktiderman/genesis-core/conversation`. The same
`ThreadMessage[]` and `InboxItem[]` render on the web and the phone.

- **`ThreadPage`:** one conversation. It fills its container.
  - Messages oldest first in a `role="log"` region, events as centred lines, attachments and a read receipt.
  - Earlier pages load near the top, with a "Load earlier" button too, and the list keeps its place while they arrive.
  - It follows the newest message only while you're at the bottom; otherwise a "Jump to latest" pill shows.
  - `firstUnreadId` adds a divider, and `jumpTo` with `onLoadUntil` goes to a message and highlights it.
  - `loading` and `updating`, and send states as data (`pending`, `paused`, `failed`, `conflict`, with `onRetry` and `onDiscard`).
  - Internal notes (`tone: "internal"`) are edged in `warning` and say so to a screen reader.
- **`ComposerBar`:** an input that grows as you type, with `modes` and a tone.
  - Enter sends; Shift+Enter adds a line. With `sendOn="mod-enter"`, Cmd/Ctrl+Enter sends instead.
  - Slots: `leading`, `trailing`, `above`.
- **`ThreadList`:** the list on its own.
- **`InboxPage`:** conversation rows: unread dot or count, a short time, a preview, a status line.
  - Each row's `swipeActions` become a "More" menu.
  - Arrow keys or j/k move between rows; `selected` marks the open one.
  - Paging, loading, error and empty states.
- **`InboxLayout`:** the three-pane inbox, with views, list, thread and an optional context sidebar. On narrow screens it shows one pane at a time, with Back.

```tsx
import { InboxLayout, InboxPage, ThreadPage, type InboxItem, type ThreadMessage } from "@marktiderman/genesis-ui";

function Inbox({ items, messages, draft, setDraft, send, openId, close }: {
  items: InboxItem[];
  messages: ThreadMessage[];
  draft: string;
  setDraft: (text: string) => void;
  send: () => void;
  openId: string | null;
  close: () => void;
}) {
  return (
    <InboxLayout
      list={<InboxPage items={items} />}
      thread={openId ? <ThreadPage messages={messages} composer={{ value: draft, onChangeText: setDraft, onSend: send }} /> : null}
      threadOpen={Boolean(openId)}
      onBack={close}
    />
  );
}
```
