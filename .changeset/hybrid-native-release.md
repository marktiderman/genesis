The native release lane is a versioned Genesis part, customised in `genesis.config.json` `release` instead of edited copies (docs/NATIVE-RELEASE.md).

- **New lane.** `templates/ci/native-release.yml` (GitHub Actions, every push to main that changes the app) publishes an over-the-air update per platform when a finished production build has the commit's runtime version and no EAS release run is open, and otherwise starts `deploy-production.yml` for that commit and platform. `deploy-production.yml` is now dispatch-only: it builds and submits, or waits for a build in progress and publishes on it, after checking `main` has no later app change. Each platform of each commit takes one path, and a failure on one platform doesn't hold the other back. New owned files: `.eas/scripts/native-release.mjs` (the lane's tested decisions), and `fingerprint.config.js` and `.fingerprintignore` (`templates/expo/`), which hash config plugins by their files and genesis-native's Swift by its path inside the package, so a Genesis release alone no longer forces a store build in a hoisted install.
- **`release` block**: `platforms`, `environment` (the GitHub environment with the secrets), `paths` (folders outside the app the bundle reads, one list for native-release, the EAS order check and pr-preview), `sentry`, `pushHook` (a script run after each release, with the release facts in `RELEASE_*`), `profile`, `channel`, `easEnvironment`, `packageManager`, and `runtimeVersion` (`"fingerprint"`, or a command that prints each platform's runtime version, matched against builds by runtime version). Validated; an app that sets nothing gets the default lane.
- **`genesis add template <set|template…>`** (and `genesis add release`): writes `release`, `eas`, `expo`, `maestro`, `ci`, `database` or `vercel` templates into an existing app and records them in the lock. A file the app already has gets `<file>.genesis-next`, never overwritten unless `--replace`. Run again after changing `release` to apply it.
- **`genesis upgrade`**: renders owned templates with `release`; with `appFolder`, refreshes and merges `native-release.yml` in the repository's `.github/workflows` (other workflows there are still only named); moves every Genesis caller pin (`@<commit> # @marktiderman/genesis@<version>`) in the repository's workflows to the release it installs, recorded as the lock's `pin`; adds the rest of the release lane to an app whose `deploy-production.yml` took the new version (and says to add `EXPO_TOKEN` before merging); lists template sets the app doesn't have.
- **`genesis init --template native`** writes the release lane and pins the CI callers to the release; it no longer copies the web-only Vercel templates. `templateTarget` reads a template's `# Copy to` line anywhere in its opening comment, so `templates/vercel/` lands at `vercel.json` and `scripts/vercel-ignore-build.sh`.
- **Doctor:** `fingerprint-plugin-files` (native pack, warn) when an app on the fingerprint runtime version loads genesis-native's config plugin without a fingerprint config that hashes plugins by their files.
