Field outputs. A host passes `outputs` (`OutputTarget[]`) to `FormBuilder`: places a field's answer may also go, such as a column of the respondent's record or a task list, each with a plain-language `label`, an optional `group`, `description` and accepted `types`, and the `prop` and `value` it sets on the field. A question whose type a target accepts gets a "Saves to" section listing them, grouped, with "Nowhere else" on top. Choosing one sets `props[prop] = value`; targets with different props can be used together, and one with the same prop replaces the other. A target is used by one question at a time unless it is `multiple`, and choosing it on another question moves it there (the inspector says so). Changing a question's type keeps the targets the new type accepts. The preview notes each one under its question ("→ goes to …"). The ops are exported too: `outputsFor`, `chosenOutputs`, `usesOutput`, `setOutput`, `clearOutputs`, `outputUsedBy` and `outputPropsFor`.

Calculated fields. The builder edits the new `calculated` type: a formula input checked as it is typed (the same checks as `parseForm`), buttons for the answers it can use, "Show as" (number, percent, text) and decimal places, and a value worked out from sample answers typed under "Try it". A new calculated field starts with the formula `0`, it has no Required switch, renaming an answer rewrites the formulas that read it, and logic compares it as a number unless it is shown as text. Like the structured types it is opt-in: `defaultPalette()` leaves out `COMPUTED_FIELD_TYPES`, so add them to `palette`. Its editor is `CALCULATED_FIELD_EDITOR` (also in `BUILT_IN_FIELD_EDITORS`), and `formulaNames(def, field)` lists the answers a formula may name.
