`genesis repo protect` puts an app's GitHub repository on Genesis's branch-protection standard: a `default` ruleset on the default branch (no deletion or force push, pull requests with resolved threads, merge or squash only, the required checks) and, for apps that release through staging batches, a `staging-branches` ruleset, plus the merge settings (delete branches on merge, auto-merge on, rebase off). The required checks are read from the app's own workflows (`app / App checks`, the review gate's `Adversarial review`), pinned to GitHub Actions; a path-filtered workflow's check is never required, since it would hold other pull requests forever. `--dry-run` prints the diff. Converging adopts an existing ruleset and keeps what Genesis doesn't name; `genesis.config.json`'s new `repo` block (`requiredChecks`, `stagingChecks`, `staging`) names the checks exactly. `genesis repo prune-staging` deletes merged staging batches through the admin bypass, with no rule turned off. The doctor's new `repo-protection` rule (warn, network only) reports drift, fixed by `repo.protect`; the setup wizard offers it as the `github.branch-protection` step.
