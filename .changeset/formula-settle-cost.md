Calculated fields stay fast when an answer a formula reads keeps changing. Each list or table column is read once per answer (kept by the answer's array) and its numbers are added up once, so a step that changes the tax rate no longer walks an unchanged 10,000-row table again. New `MAX_SETTLE_ITEMS` (50,000): the list items and table rows all of a form's formulas read together, each list or table counted once (however many of its columns are read) in form order; a calculated field that reads an answer past it, or one over `MAX_FORMULA_ITEMS`, is now blank instead of a partial total (an answer over `MAX_FORMULA_ITEMS` uses none of the allowance). Totals are kept only for lists the package builds and freezes itself, so a custom `FormulaReader` that changes a list in place gets fresh totals, and `formulaInput` builds a new list on each call. Within one engine, answers must not be changed in place; `setValue` with the array the engine already holds works it out again, and each engine (so each `validateSubmission` call) keeps its own lists, so a caller's array changed between calls is read afresh. A replay (and so `validateSubmission`) works the formulas out only for the steps that read them when no logic rule reads a calculated field, and a settle copies the answers once, not once per changed field. `parseForm` caps a form's formulas at `MAX_FORM_FORMULA_LENGTH` (20,000) characters together, since each step that changes an answer they read works them out again. A number written with letters (`1e6`, `2x`) now says "Write a number in digits only".
