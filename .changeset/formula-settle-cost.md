Calculated fields stay fast when an answer a formula reads keeps changing. Each list or table column is read once per answer (kept by the answer's array) and its numbers are added up once, so a step that changes the tax rate no longer walks an unchanged 10,000-row table again. New `MAX_SETTLE_ITEMS` (50,000): the list items and table rows all of a form's formulas read together, each answer and column counted once in form order; a calculated field that reads an answer past it, or one over `MAX_FORMULA_ITEMS`, is now blank instead of a partial total (an answer over `MAX_FORMULA_ITEMS` uses none of the allowance). Totals are kept only for lists the package builds and freezes itself, so a custom `FormulaReader` that changes a list in place gets fresh totals, and `formulaInput` builds a new list on each call. Answers must not be changed in place (pass `setValue` a new array). `parseForm` caps a form's formulas at `MAX_FORM_FORMULA_LENGTH` (20,000) characters together, since each step that changes an answer they read works them out again. A number written with letters (`1e6`, `2x`) now says "Write a number in digits only".
